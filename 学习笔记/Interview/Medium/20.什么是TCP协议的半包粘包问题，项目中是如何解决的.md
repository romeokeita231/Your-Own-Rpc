# 推荐答案

## 什么是TCP协议的半包粘包问题？项目中是如何解决的？

使用 TCP 协议网络通讯时，可能会出现半包和粘包问题。

当客户端向服务端连续发送多条消息时，**半包**是指服务端单次收到的数据比客户端单次发送的数据少，**粘包**是指服务端收到的单次收到的数据比客户端单次发送的数据多。

下面举个例子。

理想情况下，假如我们客户端连续 2 次要发送的消息是：

```java
// 第一次
Hello, server!Hello, server!Hello, server!Hello, server!
// 第二次
Hello, server!Hello, server!Hello, server!Hello, server!
```

但服务端收到的消息情况可能是：

**1）每次收到的数据更少了，这种情况叫做半包：**

```java
// 第一次
Hello, server!Hello, server!
// 第二次
Hello, server!Hello, server!Hello, server!
```

**2）每次收到的数据更多了，这种情况叫做粘包：**

```java
// 第三次
Hello, server!Hello, server!Hello, server!Hello, server!Hello, server!
```

**如何在项目中解决半包、粘包问题？**

在消息头中设置请求体的长度，服务端接收时，判断每次消息的长度是否符合预期，不完整就不读，留到下一次接收到消息时再读取。

我在代码中使用了 Vert.x 框架中内置的 RecordParser 完美解决半包粘包，它的作用是：保证下次读取到特定长度的字符。因为消息体的长度是不固定的，所以我设计 RPC 时要通过调整 RecordParser 的固定长度（变长）来解决。

那我的思路是，将读取完整的消息拆分为 2 次：

1）先完整读取请求头信息，由于请求头信息长度是固定的，可以使用 RecordParser保证每次都完整读取。

2）再根据请求头长度信息更改 RecordParser的固定长度，保证完整获取到请求体。

# 练习题

## 1. 关于TCP半包粘包问题的描述，以下哪项是正确的？()

- A. 半包是指接收方单次收到的数据比发送方单次发送的数据少
- B. 粘包是指接收方单次收到的数据比发送方单次发送的数据少
- C. 半包和粘包都是由于UDP协议不可靠特性导致的
- D. 半包和粘包问题可以通过关闭Nagle算法完全避免



## 2. 以下哪种方法不能有效解决TCP半包粘包问题？()

- A. 在消息头中添加长度字段

- C. 为每个消息添加特殊结束符
- D. 增大TCP接收缓冲区大小



## 3. 使用Vert.x框架的RecordParser解决半包粘包问题时，正确的处理流程是？()

- A. 始终使用固定长度的RecordParser

- C. 先读取固定长度的消息头，再根据头信息设置变长的RecordParser读取消息体

## 4. 关于TCP半包粘包产生的原因，以下说法错误的是？()

- A. TCP是面向流的协议，没有消息边界概念

# 答案解析

**1. 正确答案：A**

官方解析：半包是指接收方单次收到的数据比发送方单次发送的数据少（A正确），粘包则相反（B错误）。这个问题是TCP协议特有的流式传输特性导致的（C错误），关闭Nagle算法只能减少但不能完全避免该问题（D错误）。

**知识点：** TCP协议特性、半包粘包概念

**2. 正确答案：D**

官方解析：增大接收缓冲区（D）不能从根本上解决半包粘包问题，只是可能减少发生频率。其他选项都是业界常用解决方案：长度字段（A）、固定长度（B）、分隔符（C）都能有效处理消息边界问题。

**知识点：** 半包粘包解决方案、消息边界识别

**3. 正确答案：C**

官方解析：正确流程应是先读取固定长度的消息头（可以确保完整读取），再根据头信息中的长度设置RecordParser读取变长的消息体（C正确）。其他选项要么无法处理变长消息（A），要么顺序错误（B），要么实现方式不合理（D）。

**知识点：** Vert.x RecordParser、消息解析流程

**4. 正确答案：D**

官方解析：TCP协议设计并非缺陷（D错误），而是其流式特性（A正确）导致的。Nagle算法（B正确）和MTU限制（C正确）都是可能原因，但这些都可以通过应用层方案解决，不是必然出现的。

**知识点：** TCP协议原理、半包粘包成因

**5. 正确答案：B**

官方解析：解决半包粘包最关键是设计消息边界识别机制（B正确）。序列化协议选择（A）与之无关，禁用TCP优化（C）不可取且不必要，改用UDP（D）会引入其他问题。边界识别可以通过长度字段、分隔符等方式实现。

**知识点：** RPC协议设计、消息边界识别
