# 推荐答案

## 在项目中是如何实现消费方调用的，为什么选用JDK动态代理和工厂模式

RPC 框架的优势在于消费方可以像调用本地方法一样调用服务提供者的服务，为了实现这点，我使用了动态代理技术。

先介绍整个调用流程：

1. 消费方通过代理工厂，根据指定的服务类型获取代理对象
2. 通过实现 InvocationHandler 接口实现 JDK 动态代理，在 invoke 方法中根据 method 等参数构造请求对象
3. 通过注册中心进行服务发现，以获取提供该服务的所有服务提供者的信息
4. 使用负载均衡选择一个服务提供者
5. 发起 RPC 请求并得到响应结果

**为什么使用 JDK 动态代理？**

JDK 动态代理是 Java 提供的一种原生代理机制，允许开发者在运行时动态地创建代理类，这种机制主要用于接口的代理，符合我项目的需求。

选用它的原因：

1. JDK 动态代理作为 Java 标准库的一部分，无需引入任何第三方依赖即可使用。
2. 相比于 CGLIB 等动态生成字节码的动态代理实现，JDK 动态代理的性能更高。
3. JDK 动态代理能够在不同的 Java 平台上运行，具有良好的跨平台性。

**为什么选用工厂模式？**

1. **更灵活：** 通过工厂模式提供的 "根据类型获取代理类" 的方法，我能够根据需要动态地选择合适的代理对象类型进行创建。
2. **解耦合：** 将创建代理对象的过程进行封装，调用方不需要了解具体的对象创建细节，使代码更利于维护。

此外，我还可以在工厂类中结合双检锁单例模式，实现代理对象的延迟初始化。

# 练习题

## 1. 在RPC框架中，使用JDK动态代理的主要优势是什么？()

- A. 作为Java标准库的一部分，无需引入第三方依赖
- B. 可以代理没有实现接口的类
- C. 生成的代理类执行效率比CGLIB更高
- D. 支持在编译时就确定代理关系



## 2. 关于RPC框架中工厂模式的应用，以下说法错误的是？()

- A. 工厂模式可以动态选择合适的代理对象类型
- B. 工厂模式将对象创建细节暴露给调用方
- C. 工厂模式可以与单例模式结合使用
- D. 工厂模式有利于代码维护和解耦



## 3. 以下哪项不是JDK动态代理在RPC框架中的典型使用场景？()

- A. 在运行时动态创建接口代理类
- B. 在invoke方法中构造RPC请求对象
- C. 直接代理没有接口的实体类
- D. 通过InvocationHandler接口实现方法拦截



## 4. 在RPC调用流程中，以下哪一步不是必须由动态代理完成的？()

- A. 根据method参数构造请求对象
- B. 通过注册中心进行服务发现
- C. 使用负载均衡选择服务提供者
- D. 发起实际的网络请求



## 5. 关于工厂模式在RPC框架中的应用，以下哪种实现方式最能提升性能？()

- A. 每次调用都创建新的代理对象
- B. 使用简单工厂直接返回新实例
- C. 结合双检锁单例模式实现延迟初始化
- D. 通过原型模式复制已有实例

# 答案解析

**1. 正确答案：A**

官方解析：JDK动态代理是Java原生支持的代理机制，主要优势在于无需引入第三方依赖即可使用。选项B错误，JDK动态代理只能代理接口；选项C错误，CGLIB的执行效率通常比JDK动态代理更高；选项D错误，动态代理是在运行时确定代理关系的。

**2. 正确答案：B**

官方解析：工厂模式的核心优势之一就是封装对象创建细节，使调用方无需了解具体实现，因此选项B说法错误。其他选项都是工厂模式的正确应用场景。

**3. 正确答案：C**

官方解析：JDK动态代理只能代理接口，不能直接代理没有接口的实体类，这是它的主要限制。其他选项都是JDK动态代理在RPC框架中的典型使用方式。

**4. 正确答案：B**

官方解析：服务发现是通过注册中心完成的，不是动态代理的职责。动态代理主要负责方法调用的拦截和转发，包括构造请求、负载均衡和发起请求等操作。

**5. 正确答案：C**

官方解析：结合双检锁单例模式可以实现代理对象的延迟初始化和复用，避免重复创建代理对象带来的性能开销，是最佳实践。其他选项要么会产生性能损耗，要么不能保证线程安全。
